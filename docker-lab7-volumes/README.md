# Docker lab 7 — PostgreSQL и постоянные данные

Сквозная рабочая нумерация: 7. Оригинальное задание: ЛР3 из `Docker_Volumes_EnvVars.pdf`, страницы 19–22. Здесь сохранены схема, 4 студента и 3 курса из исходника. Проверки выполнены реальным PostgreSQL, а не подменой Docker-команд.

Нужны Docker Engine/Desktop и Python 3 на компьютере. Используется `postgres:15-alpine`, чтобы путь `/var/lib/postgresql/data` и major совпадали с заданием. Порт PostgreSQL не публикуется: SQL выполняется через `docker exec`.

## Выполнение

```bash
chmod +x commands.sh cleanup.sh
./commands.sh
```

Для сохранения физического архива в выбранной папке вне Git-репозитория:

```bash
./commands.sh --run-id my-first-run --backup-dir /absolute/path/to/backups/my-first-run
```

У каждого запуска отдельные имена `devops-lab7-RUN_ID-*` и labels `devops.owner=codex-devops-labs`, `devops.lab=7`, `devops.run=RUN_ID`. Существующий run ID отклоняется без перезаписи его БД. Глобальные prune и операции с чужими контейнерами не используются.

До создания env-файла и Docker-ресурсов выполняется безусловный inspect каждого планируемого имени контейнера и volume. Занятое имя блокирует запуск даже при отсутствии наших labels. После `docker volume create` принадлежность volume проверяется повторно до монтирования: эта команда сама по себе умеет возвращать уже существующий объект.

Скрипт создаёт named volume, запускает PostgreSQL, выполняет init.sql, сравнивает данные до/после удаления контейнера, делает SQL dump и восстанавливает его в отдельный volume. Затем штатно останавливает исходную БД, архивирует её volume и проверяет физическое восстановление ещё в одном отдельном volume. Сравнение включает все значения обеих таблиц и timestamps.

`evidence/verification.json` содержит реальные результаты, snapshots, IDs и names ресурсов. `evidence/backup.sql` — настоящий учебный SQL dump. `REPORT.md` показывает результат последнего запуска и путь/размер/SHA-256 физического архива. Физический tar не коммитится: локальная переданная копия находится в `.local/backups/20261104-actual/`, исключённой из Git. Случайный локальный пароль используется только для инициализации и не выводится в отчёт; временный env-файл удаляется после проверки.

После проверки все PostgreSQL-контейнеры этого запуска остановлены, volumes сохранены. Это позволяет отдельно запустить сохранённый контейнер командой `docker start ИМЯ` и проверить таблицы:

```bash
docker exec ИМЯ psql -U student -d university -c 'SELECT * FROM students ORDER BY id;'
```

Подставь имя из evidence. Перед SQL дождись `pg_isready`. После ручной проверки снова останови контейнер.

## Очистка только выбранного запуска

```bash
./cleanup.sh RUN_ID
```

Удаляет контейнеры выбранного lab7 run ID; volumes сохраняются. Для отдельного осознанного удаления **данных**:

```bash
./cleanup.sh RUN_ID --delete-data
```

Внешний физический архив и evidence автоматически не удаляются. Volume не является резервной копией; проверенное восстановление подтверждается отдельными SQL и physical restore в этом проекте.
